# 数据导入与批量操作

先完成 `SKILL.md` 的 Setup，确认用户明确指定的目标工厂；仅在需要核对新接口或字段时读取实时 OpenAPI，并阅读源项目的 `DATA_FORMATS.md`（若存在）。只使用 `/api/v1` 支持的潜客 CSV 和单个开发关系聊天导入；整理、预览或转换数据不等于授权写入。

## 潜客 CSV

1. 保留原始 CSV，不覆盖源文件。只映射可验证的客户字段；`displayName` 必填，邮箱和 LinkedIn URL 必须有效，客户时区必须是 IANA 时区。未映射字段单列，不塞入含义不同的字段。
2. 按邮箱、WhatsApp、LinkedIn，以及“姓名 + 公司”检查当前工厂的现有客户。仅同名或相似名不能自动合并；其他工厂的客户不参与本厂去重。
3. 以 `{ "csvText": "...", "fileName": "..." }` 调用 `POST /api/v1/factories/{factoryId}/imports/prospects/preview`。按实际响应报告指纹、有效、错误和重复统计；预览不写业务数据。
4. 用户确认目标工厂、原 CSV、预览指纹、预计写入量和错误/重复处理后，用完全相同的 `csvText`、可选 `fileName`，加上原 `expectedFingerprint` 和 `confirmation: "IMPORT_PROSPECTS"` 调用 `confirm`。预览和确认使用不同的稳定幂等键。
5. 确认端点会在写入前创建 SQLite 在线备份；备份失败即停止。核对响应中的实际 `backupPath`、导入结果、回显预览和导入批次，再重新读取当前工厂客户及开发关系。

不要自行修改错误行后沿用旧指纹；源内容或参数变化必须重新预览并重新确认。

## 完整聊天

1. 确认目标工厂、唯一 `leadId`、完整原始聊天正文，以及至少一个我方发送者别名。聊天导入不能创建客户或开发关系。
2. 以 `{ "leadId", "transcript", "senderAliases": [...] }` 调用 `POST /api/v1/factories/{factoryId}/imports/chats/preview`，核对指纹、消息总数、入站、出站、重复和样例。方向错误时修正别名并重新预览。
3. 用户确认 lead、完整原文、别名、方向和统计后，用完全相同的参数，加上原 `expectedFingerprint` 和 `confirmation: "IMPORT_CHAT"` 调用 `confirm`。预览和确认使用不同的稳定幂等键。
4. 核对实际 `backupPath`、导入/跳过结果、回显预览、导入批次及该 lead 的互动。入站消息可推进到已回复/待判断，但不代表有效回复、真实需求或商机。

不要只导入节选冒充完整聊天，不要补造时间、发送者或方向；无法可靠解析时停止并报告具体问题。

## 结果驱动的批量操作

1. 固定目标工厂、筛选条件和记录 ID 集合，列出旧值、新值、预计数量和无法自动判断的记录。
2. 优先使用正式批量入口：潜客导入、聊天导入，或跟进策略的 `application-preview` + `apply`。每个预览都只对应当时的源内容、参数或候选名单。
3. 没有批量入口时，以可核对的小批次逐条调用正式 API。每个逻辑动作使用独立稳定幂等键；适用时带最新 `expectedUpdatedAt`。
4. 回复分类、停止/恢复联系、背调审核、真实互动、商机创建/输赢以及每次导入或策略应用，都按具体对象或最新预览取得用户确认。
5. 每批提交后重新 GET，分类报告成功、未变化、跳过和错误。查询结果、版本、指纹或工厂归属变化时停止剩余批次并重新预览。

不存在全库 JSON 合并、旧快照迁移或恢复业务入口。此类请求属于技术管理员的部署/恢复流程，必须转到工作台 `DEPLOYMENTS.md`，不能通过 UI、`/api/v1`、SQLite 命令或临时脚本代办。
